Options, files, columns

The reference: every option of generate.py and step_total.py, the layout of the package and of an example folder, and every file the steps write, with its columns. The numbers in the examples are kermadectonga2_v9's; what a segmented run adds is listed in Files a segmented run adds, from kermadectonga2_v9seg.

What each step reads, with --ptha false and --ptha true

step_total.py options

OptionWhat it does
(none)runs steps 1 to 9 in order, each as its own process; stops at the first required step that fails; 7b and 8 are optional (a failure is reported and the run goes on)
--skip-officialdoes not try step 8 (no R needed)
--skip-hsdoes not run step 7b
--auto-clippasses --auto-clip to step 1, cutting the along-strike columns a previous run's step 3 check flagged as sitting on a different plate boundary, using a window derived from the mesh (no lon/lat from you). To keep a log: .venv/Scripts/python.exe <folder>/steps/step_total.py > <folder>/run_final.log 2>&1; the examples' logs are run_final.log. The single steps take their own options: step6_write_input.py --force, step7b_stochastic_slip.py --max-placements-per-mw N --max-fields-per-mw N, step8_official.py --download-hs.

Known limits

  • Segmentation follows Berryman, not PTHA18's own table. v9 runs LEVEL 0 with --segmented true (without it, every zone is one unsegmented source at weight 1, as in v8). The boundaries come from Berryman et al. (2015) Table 3.1's segment end points, never from PTHA18's sourcezone_parameters.csv: within 0 to 2 columns of PTHA18's on PTHA18's own meshes, with different counts only where PTHA18 merged Berryman's segments (Patagonia, eastern Alaska) or added one (Arakan). The method is PTHA18's, checked scenario by scenario from PTHA18's own inputs (validate_v9.py events_segmented); step 8 of a segmented example runs PTHA18's segmented model for the comparison. See LEVEL 0.
  • Automatic contours, not hand edits. The contours are 1 to 3 km from PTHA18's (the trench line 1.6 to 4.1 km seaward), and the zone's ends are cut by a rule. Where PTHA18 extended a zone beyond the SLAB data by hand (puysegur2), this package does not.
  • SLAB coverage. A zone can only be as long as its SLAB data: southamerica's SLAB1.0 stops near 43 deg S, PTHA18's zone continues to Tierra del Fuego.
  • --clip is not checked for windows that cut through a neighbouring slab: look at the step 1 figure.
  • Puysegur's convergence. Bird by default here (25.6 mm/yr); PTHA18 used a constant 35 mm/yr (how to reproduce it).
  • HS and VAUS are random: compared with PTHA18 statistically, never field by field. They never change a rate. Their generator assumes equal cells inside a footprint (details).
  • v10 / v10_q: with --rupture-size local the event list no longer matches PTHA18's event by event; no rupture is smaller than one cell; the cells themselves are not reshaped (all limitations).
  • The report's map needs an internet connection (Leaflet and Esri tiles).
