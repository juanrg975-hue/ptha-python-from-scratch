8. The official PTHA18 run

Step 8 answers one question: what would this same engine give with PTHA18's own inputs? It takes PTHA18's published mesh, its parameters, its convergence and its observed earthquakes, and runs them through exactly the engine step 7 uses. The difference between the two runs is then only the inputs, never the code. It is optional, and needs R.

At a glance

NeedsR with the rptha package (Rscript on the PATH or in C:\Program Files\R\); a zone PTHA18 modelled; an internet connection the first time.
WritesROOT/inputs/input_<zone>.json (shared), the example's copy inputs/input_<zone>_official.json, outputs_official/ and outputs_official/ptha18_reference/; a segmented example also runs/python/<zone>_official_segmented/ and ptha18_reference/official_segments.json.

Why it needs R

PTHA18's logic-tree weights after its Bayesian update, and its parameter table per zone, live inside R objects of its saved session: functions whose values only exist once R runs them. No Python reader of R data files can get at them. So step 8 calls R once, through official_ptha_data/fetch_official_inputs.py, to extract the official tree, and from then on everything is Python. Once a zone's tree is extracted, a re-run reuses it instead of reading the session again, but step 8 still checks that Rscript is installed before it starts.

Zones PTHA18 never modelledcalabria2, caribbean2 and antilles2 have no official run: the saved session has no entry for them. Step 8 then stops with a message, step_total.py reports it and carries on, and the report leaves out the comparison sections. Steps 1 to 7 and 9 are complete without it.

What it does, in order

  1. Download (once) PTHA18's saved session (1.34 GB) and the zone's cell table unit_source_statistics_<zone>.nc from NCI's public THREDDS server.
  2. Extract with R the official logic tree and each zone's parameters.
  3. Read the zone's row of PTHA18's sourcezone_parameters.csv: coupling, b-value, largest observed magnitude, whether it uses Bird's convergence.
  4. Recover the convergence from the session (PTHA18 stores the slip on the fault, the script inverts it back to the horizontal rate).
  5. Write inputs/input_<zone>.json, every field with a _provenance note, geometry mode official_statistics (the engine reads PTHA18's cell table directly, no meshing).
  6. Check it against the session: area, mean dip, convergence, a control zone and the Mw_max axis.
  7. Add PTHA18's Bird model when the zone uses Bird: the per-column profiles computed on PTHA18's own mesh with lib/bird_convergence.py, checked to reproduce the official convergence.
  8. Add PTHA18's segments (v9), only when this example is segmented: every segment row of sourcezone_parameters.csv for the zone (its columns of PTHA18's mesh, coupling, b range, mw_max_observed) with the GCMT events the saved session gives that segment. The run is then PTHA18's own segmented model, written to runs/python/<zone>_official_segmented/. validate_v9.py official_segments and events_segmented check that this reproduces PTHA18's segment trees and published scenario rates exactly.
  9. Run the engine on the example's copy of that file and copy its output to outputs_official/.
  10. Write the PTHA18 reference for the report into outputs_official/ptha18_reference/ (below).

Why the official run is trustworthyWith PTHA18's own inputs, this engine reproduces PTHA18's published results: every branch's GR a value to 3e-12, and every scenario's mean rate within 1e-10 and its percentiles within 1e-8 on the zones checked. See Validation and tests.

Run it

.venv/Scripts/python.exe kermadectonga2_v9/steps/step8_official.py
.venv/Scripts/python.exe kermadectonga2_v9/steps/step8_official.py --download-hs   # also PTHA18's HS/VAUS catalogues, for step 7b's comparison
.venv/Scripts/python.exe kermadectonga2_v9/steps/step9_report.py   # to see the comparison

# a SEGMENTED example: the same two commands on its folder; step 8 runs PTHA18's segmented model
.venv/Scripts/python.exe kermadectonga2_v9seg/steps/step8_official.py
.venv/Scripts/python.exe kermadectonga2_v9seg/steps/step9_report.py

The first run on a machine downloads the session and loads it into R, which takes minutes; later runs, for any zone, reuse it. step_total.py --skip-official skips step 8 entirely.
