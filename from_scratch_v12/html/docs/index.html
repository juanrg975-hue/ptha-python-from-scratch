from_scratch_v12: PTHA18 earthquake sources from public data

One command builds a complete earthquake source model for a subduction zone, the way the Australian tsunami hazard assessment PTHA18 built its own: the fault surface cut into cells, how fast the plates move, which earthquakes have happened, and how often every possible earthquake is expected. It uses public data only, and every step is checked against the files PTHA18 published.

At a glance

Four public data sets go in on the left. Nine steps turn them into a source model on the right. PTHA18's own published files (bottom) are used only to check the result, never to build it.

What it does, in five sentences

  1. Step 1 downloads the depth of the sinking plate (USGS SLAB) and draws depth lines every 5 km, measured from the nearby trench, down to the depth where large earthquakes stop; it cuts the zone's ends square where the data ends crookedly. Step 1, clean ends
  2. Step 2 cuts that surface into cells of about 50 km (the unit sources) with rptha's own method, and with --discretizer optimal repairs the mesh only if a cell is folded, collapsed or overlapping. Step 2, optimal, lm and mid
  3. Step 3 reads how fast the plates converge under every column of cells from Bird's (2003) plate model, exactly as PTHA18 does; steps 4 and 5 pick the earthquakes of the Global CMT catalogue that happened on this interface. Step 3, steps 4-5
  4. Steps 6 and 7 put everything in one input file and run PTHA18's logic tree: 32,000 combinations of coupling, b-value and maximum magnitude, each balanced against the plate motion, re-weighted by the observed earthquakes, and summarised into rates with uncertainty. Step 6, step 7
  5. Step 9 writes report.html with every number and figure, including the mesh on a real map; step 8 (optional, needs R) runs PTHA18's own inputs through the same engine so the two can be compared. Step 8, reading the report, what step 8 is the only thing that touches PTHA18

The one-minute run

From ptha18_logic_tree_test/, generate a folder for a zone and run all its steps. Quick start explains every option and has a command builder.

.venv/Scripts/python.exe from_scratch_v12/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_v9 --ptha false --discretizer optimal
.venv/Scripts/python.exe kermadectonga2_v9/steps/step_total.py --skip-hs     # steps 1-9; step 8 needs R
start kermadectonga2_v9/report.html

How far to trust it

proven equal to PTHA18

  • Given PTHA18's own contours, the mesh has PTHA18's exact size on all 14 zones checked.
  • Given PTHA18's own inputs, all 32,000 branches match PTHA18's tables (4 zones checked), and every segment's (7 segmented zones).
  • The rate of every earthquake scenario, and its uncertainty, match PTHA18's published files (mean within 1e-10, percentiles within 8e-9) on 4 unsegmented zones, and on 7 segmented zones, where PTHA18's rates add the unsegmented model and every segment a rupture touches.
  • The convergence (to about 1e-15) and the earthquake selection (identical lists on 8 zones and on every segment of 4) reproduce PTHA18's.

Details: Validation and tests.

different by design

  • The contours come from SLAB automatically, while PTHA18 edited its own by hand, so meshes differ by a few km and sometimes at the ends.
  • Segmented zones (LEVEL 0) are reproduced in v9, with --segmented true: the zone is split along strike, the unsegmented branch and the union of segments each take weight 0.5, and the segments sum within that union. Boundaries come from Berryman et al. (2015) Table 3.1's segment end points, the table PTHA18 took its segments from, so a segmented run stays public-data-only under --ptha false and still lands within 0 to 2 columns of PTHA18's boundaries on PTHA18's own meshes. Without the flag every zone is run unsegmented, exactly as v8 did.
  • Where PTHA18 extended a zone beyond the SLAB data by hand (puysegur2), this package does not invent geometry.
  • v10 / v10_q, opt-in: --rupture-size local sizes each uniform-slip rupture from its own cells and weights it with q. Not PTHA18's procedure: the event list no longer matches PTHA18's event by event, while the earthquakes per magnitude stay identical. The trench ramp rule (default on) trims a trench end that is the edge of the SLAB data (details).
