Quick start

Three commands: generate a folder for a zone, run it, open the report. This page explains each, gives the exact commands of the 8 examples, and has a command builder. All commands are run from ptha18_logic_tree_test/.

At a glance

What you need

  • Python: the virtual environment .venv/ of ptha18_logic_tree_test/ (numpy, scipy, pandas, matplotlib, geopandas, shapely, pyproj, netCDF4, Pillow). Every command below uses .venv/Scripts/python.exe.
  • Internet the first time: the SLAB raster (USGS, saved in each run folder's data/slab1/ or data/slab2/), the GCMT catalogue, and for step 8 PTHA18's files (NCI). Nothing is downloaded twice inside the same folder.
  • R with rptha, only for step 8 (the official PTHA18 run). Without R, run with --skip-official; everything else works.
If step 1 stops with a download error (HTTP 403)Either SLAB host can block a scripted download outright: ScienceBase (SLAB2.0) with a "Just a moment..." Cloudflare challenge, earthquake.usgs.gov (SLAB1.0) with its own web-application firewall. Neither clears by retrying. The error message step 1 prints already has the exact link for your region and the folder to save the file into: get it by hand in a normal browser and re-run the step. Full details: Troubleshooting.

Check the installation with the tests (about 10 seconds): .venv/Scripts/python.exe -m pytest from_scratch_v12/pyptha_v12/tests -q, which ends here with 187 passed, 15 skipped (tests that need PTHA18's extracted files are skipped while those files are absent). The 15 compare against PTHA18's official inputs, which the package does not ship; once step 8 has extracted them (validation), all of them run and pass.

1. Generate a folder

.venv/Scripts/python.exe from_scratch_v12/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_v9 --ptha false --discretizer optimal
.venv/Scripts/python.exe from_scratch_v12/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_v9seg --ptha false --segmented true   # the same zone with LEVEL 0 segments
ArgumentMeaningDefault
kermadec (name)the SLAB region, as a word; list_regions.py lists all 27required
--zonePTHA18's name for the zone. It sets the SLAB version (a name ending in 2 uses SLAB2.0) and the literature values. All valid names, with the command for each: Zones you can runguessed from the name
--folderfolder to create; if it exists, _2, _3 ... is appended<name>_v12
--ptha falsepublic data only (with the default --convergence bird): steps 1 to 7 and 9 read no file of PTHA18 or of rptha (50 km cells, rptha's row rule, Bird's public catalogue); only step 8 reads PTHA18, for the comparison. Recommended; needed for zones PTHA18 never modelledtrue
--discretizer optimalrptha's mesh, repaired only if broken (details)optimal
--segmented true|falsenew in v9, LEVEL 0: true splits the zone along strike at Berryman et al. (2015) Table 3.1's segment end points (the segments PTHA18 used; --segment-boundaries bird for Bird's plate pairs) and runs the segmented tree (unsegmented branch 0.5, union of segments 0.5, segments summed within the union); public data only under --ptha false. false: one unsegmented zone, v8's pipeline (with v9's Berryman zone values: coupling from the Whole Margin row, Mw max observed as the largest known earthquake). If step 3 warns that the mesh runs past its own plate boundary, re-run with step_total.py --auto-clip before trusting the segments (why). Recipe with the official comparison: below; everything about it: Segmented vs unsegmentedfalse
--segment-boundaries berryman|birdv9, only with --segmented true: where the segments end. berryman: at the trench end points of Berryman et al. (2015) Table 3.1, the segments PTHA18 used. bird: where Bird (2003)'s plate pair changes (misses Hikurangi on kermadectonga2)berryman
--columns trench|averagehow many cells along strike: trench, rptha's and PTHA18's rule (trench length / 50 km); average, the average row length / 50 km, for tight arcs such as calabria2, not PTHA18's procedure (details)trench
--convergence bird|bird-griffinwhich plate-motion table step 3 reads: Bird (2003)'s public catalogue, or the table PTHA18 used (Bird plus Jonathan Griffin's traces). bird-griffin is PTHA18's own table, so with it the run is no longer public data only. It matters mostly where PTHA18 used Griffin's traces (per zone); generate.py prints a note for the zonebird
--clip LON_MIN,LON_MAX,LAT_MIN,LAT_MAXuse only part of the SLAB raster (details)none
--ida ScienceBase item id, to force the SLAB2.0 regionfrom the name
--rupture-size rptha|localv10: how many cells each uniform-slip rupture gets. rptha: PTHA18's rule, one block per magnitude. local: a block per placement from the real km of its cells, plus q (v10_q). Use it where cells differ a lot (calabria2, caribbean2) (details)rptha
--trench-ramp on|offv10_q: trims a trench end that climbs in depth like a ramp (the edge of the SLAB data) before the datum is built. Changes hellenic, caribbean/antilles and kermadectonga2 (details)on
--trench-ends LON1,LAT1,LON2,LAT2the zone's two ends, for a zone that is one part of a SLAB region (default for the Hellenic zones: Berryman et al.'s end points) (details)none
--variable-mu on|offv11: on also runs step 7c, PTHA18's variable shear modulus rates, next to the constant ones (details)off
--mesh-file FILEv12: use your own quadrilateral mesh (one line per unit source, its 4 corners as lon lat depth) instead of building one from SLAB. Steps 1-2 do not use SLAB; steps 3-9 run unchanged. Must be a structured mesh, rows x columns (details)none (SLAB)
--mesh-depth-units auto|m|kmv12, with --mesh-file: the file's depth unit. auto: metres if any |depth| > 200. The sign is detectedauto

With the defaults a v12 folder is a v9 one (except where the trench ramp rule trims a trench end); every option after --clip is opt-in. The examples on this page keep the names of the v9 folders they reproduce.

.venv/Scripts/python.exe from_scratch_v12/list_regions.py     # the 27 SLAB regions and PTHA18 zone guesses

Every option in detail: Options, files, columns.

2. Run it

.venv/Scripts/python.exe kermadectonga2_v9/steps/step_total.py                    # steps 1-9, with 7b and 8 (and 7c if generated with --variable-mu on)
.venv/Scripts/python.exe kermadectonga2_v9/steps/step_total.py --skip-official    # no R needed
.venv/Scripts/python.exe kermadectonga2_v9/steps/step_total.py --skip-hs          # no HS/VAUS slip fields (and no step 7c, which needs them)

Or one step at a time, in order: steps/step1_fetch_slab2.py to steps/step9_report.py. Each step prints what it read, did and wrote, and ends with the name of the next one. The folder's RUN.html lists the commands with notes.

Timing with the data already downloaded: about 1 to 4 minutes per zone (measured on the examples).

3. Open the report

start kermadectonga2_v9/report.html

A segmented run, with its official comparison

  
The same zone with LEVEL 0 segments (v9). Step 8 then runs PTHA18's own segmented model, so the report's LEVEL 0 section compares segments with segments (it needs R, as any step 8: official run). kurilsjapan must run steps 1-3 first so step 3 can flag the Izu-Bonin tail, then the clipped run.

  
.venv/Scripts/python.exe from_scratch_v12/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_v9seg --ptha false --segmented true
.venv/Scripts/python.exe kermadectonga2_v9seg/steps/step_total.py --skip-hs

.venv/Scripts/python.exe from_scratch_v12/generate.py kuril --zone kurilsjapan --folder kurilsjapan_v9seg --ptha false --segmented true
.venv/Scripts/python.exe kurilsjapan_v9seg/steps/step1_fetch_slab2.py
.venv/Scripts/python.exe kurilsjapan_v9seg/steps/step2_build_grid.py
.venv/Scripts/python.exe kurilsjapan_v9seg/steps/step3_convergence.py
.venv/Scripts/python.exe kurilsjapan_v9seg/steps/step_total.py --skip-hs --auto-clip   # the clipped mesh, steps 1-9

# only the official comparison again, after steps 1-7
.venv/Scripts/python.exe kermadectonga2_v9seg/steps/step8_official.py
.venv/Scripts/python.exe kermadectonga2_v9seg/steps/step9_report.py

  
The unsegmented twins are the same commands without --segmented true (folders kermadectonga2_v9, kurilsjapan_v9, kurilsjapan also with --auto-clip). These four folders exist and are compared in html/segmented_vs_unsegmented.html at the package root.

For kurilsjapan run steps 1 to 3 first, then step_total.py --skip-hs --auto-clip, which cuts the Izu-Bonin tail step 3 flags (why). These are the unsegmented runs (v8's model; the numbers differ from v8's only where v9 changed the zone's Berryman values); add --segmented true to any of them for LEVEL 0 with segments, which is only meaningful where Berryman divides the zone into segments (kermadectonga2, kurilsjapan and southamerica here; makran2, puysegur2, calabria2, caribbean2 and antilles2 are single segments).
