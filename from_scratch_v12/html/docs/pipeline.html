The pipeline, step by step

Nine small scripts, run in order, each reading only what the previous ones wrote to disk. This page shows how they fit together: what each one reads, does and writes, where every number of the final result comes from, what can go wrong at each step and how long it takes.

The diagram

Click a box to see what that step reads, does and writes. The three input lanes on the left are the three kinds of evidence PTHA18 combines: the geometry of the fault, the plate convergence, and the observed earthquakes.

Data flow: who reads what

Every step writes to the example folder (for example kermadectonga2_v9/) and the next steps read those files back. Nothing is passed in memory, so any step can be re-run alone after editing its inputs. Paths are relative to the example folder.

Why the mesh is built three times but is always the same mesh steps 2, 7, 9

Step 7 (the engine) and step 9 (the report) rebuild the mesh from the geometry block of the input JSON, because a user may have edited that block by hand after step 6 (for example to force a number of rows). To avoid two different meshes, the grid is cached: step 2 saves unit_source_grid.npy with a fingerprint of the exact inputs (contours, lengths, rows, discretiser). Later steps reuse the saved grid only if the fingerprint matches, and rebuild it otherwise. The log line mesh: reusing step 2's grid (... fingerprint matches) says which happened. Details: the grid cache.

What each step checks, and what it prints when something is wrong

Every required step stops with a clear message instead of passing a bad result on. The main checks:

StepCheckWhat you see
1no trench-like edge on the raster; a contour level missing, closed, or much shorter than the level above itthe step stops and names the level; the step 1 figure shows the contours it found
1an end is crooked or tapersnot an error: the end is cut, and the log says CUT, ...; the new end is N deg off square
2folded (bow-tie), collapsed or overlapping cellsmesh check: 0 folded (bow-tied) cells, 0 collapsed cells, 0.00% overlapping area; with optimal, a broken mesh is repaired and the log says which repair was used
3no Bird segment near the zone, even in Bird's untrimmed cataloguethe step stops: no Bird segments found near this zone ...
4a monthly GCMT file that is not publishednot an error: skipped (HTTP Error 404); the window ends in 2017, so these months are not used
3, 5, 6, 9a file from an earlier step is missingthe step stops and names the step to run first, for example missing .../convergence.txt Run step3_convergence.py first.
generate.pyno Berryman et al. (2015) mapping for a zone PTHA18 never modelledthe missing values are marked NOT AVAILABLE and step 1 stops (it needs the seismogenic cutoff). Add the zone to ZONE_TO_BERRYMAN_SEGMENTS and ZONE_DOMINANT_SEGMENT in lib/berryman_params.py, then run generate.py again
7the convergence profile has no positive valuethe step stops: no tectonic moment on this source
8R missing, or a zone PTHA18 never modelledoptional: step_total prints why and continues; the report leaves out the comparison

The exact messages and what to do about them are in troubleshooting.

First run on a new machineThe first time, step 1 downloads the SLAB data (tens of MB per region), step 4 downloads the GCMT catalogue, and step 8 downloads PTHA18's saved R session (1.34 GB, once for all zones; loading it into R takes minutes).
